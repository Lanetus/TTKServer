# TTKServer

TTK = **Trusted Transport Kit**.

Rust HTTP/3 (QUIC) server meant to run inside an AWS Nitro Enclave. It acts as a RATS (RFC 9334) **Attester**: it generates an ephemeral TLS key, gets an NSM Attestation Document whose `user_data` is bound to that key, embeds the evidence in a self-signed X.509 cert (custom extension), and serves the evidence over HTTP/3. Two enclave nodes are built on it: the **relay** (forwards onion-routed `POST /faf` requests) and the **terminal** (the last hop, decrypts the message). A companion `client` binary attests the nodes and sends a `/faf` message through a relay to a terminal. Appraisal against reference values (PCRs) happens outside this repo.

## Context & File Access Rules
- **Do NOT read or search inside:** `docs/`, `target/`, or `out/`.
- Only inspect the crates' `src/` and `tests/` unless explicitly instructed otherwise.
- `docs/src` are NOT for reference. We use them to generate the architectural documentation.

## Layout (Cargo workspace, members in `crates/`; root `Cargo.toml` holds `[workspace.package]` version/metadata and `[workspace.dependencies]`)
- `crates/core/` — crate `ttk-core` (lib `ttk_core`): what server and client share, so `ttk-ra-client` does not depend on `ttk-ra-server`. Re-exported by `ttk-ra-server` at its old paths (`attestation::{cmw, media_type}`, `server::{ATTESTATION_OID, PARENT_CID, BoxError}`, `vsock`).
  - `src/lib.rs` — `media_type` (CMW types: Nitro/TDX/SGX records, SEV-SNP collection `{report, vcek}`), `ATTESTATION_OID`, `PARENT_CID` (3), `MOCK_NITRO_ROOT_CERT` (`mock_nitro_root.der`; its key stays in `ttk-ra-server`), `TTK_ROOT_CA_PEM` (`TTK_Root_CA.pem`, the only root `POST /certificate` accepts); `BoxError` (`Box<dyn Error>`, not `Send + Sync`); re-exports `Cmw`, `CmwRecord`, `CmwCollection`, `CmwType`, `ImageTrustStore`, `RootSignerTrustStore`.
  - `src/cmw.rs` — RATS Conceptual Message Wrapper (`draft-ietf-rats-msg-wrap`), CBOR only: `Cmw` (record `[type, value, ?ind]` / collection with `__cmwc_t`), `ind` bits, `Cmw::evidence`.
  - `src/image_trust.rs` — TEE-agnostic (no Nitro/PCR names): trait `ImageTrustStore` (also at the crate root): `builtin()`, `image_allowlist()`, `measurement()` (`ImageMeasurement::Image` default, or `Signer`; the per-TEE field is chosen by `ttk_ra_client::verifier::image_measurement`). `RootSignerTrustStore` (also at the crate root): signers pinned for the root servers (`src/certs/root_signer_allowlist.txt`, empty = no genuine root accepted). Implemented by `ttk_root::FileImageTrustStore` (txt file) and `ttk_ra_client::RootImageTrustStore` (fetched from the root servers). Also `parse_image_allowlist` (64 or 96 hex chars per line, `MEASUREMENT_LENGTHS`, all-zero refused) and the `/root-attestation` wire format (`RootAttestation` `{measurements: [hex…]}`, `ROOT_ATTESTATION_PATH`). Re-exported at the `ttk_ra_client` root.
  - `src/fresh_evidence.rs` — `FreshEvidence` (also at the crate root): the `POST /evidence` response, CMW collection `media_type::FRESH_EVIDENCE_COLLECTION` `{evidence: <TEE CMW>, certificate: <DER, PKIX_CERT>}`; `to_cmw`/`from_cmw`/`from_cbor_bytes`; `report_data` (64-byte TDX/SEV-SNP report data: user_data zero-padded, or with a nonce user_data ‖ SHA-256(nonce)), shared by the `tsm` providers and the verifier.
  - `src/file_message.rs` — file service wire format (CBOR): `FileRequest` (`{"type": "upload"|"download", "body": bstr}`), `FileResponse` (`{"response": bstr}` / `{"error": "not_found"}`), `FileError`, `SHA256_LEN`; used by `ttk_storage` and the `client` bin (not re-exported: tests import it from `ttk_core`).
  - `src/faf.rs` — the `/faf` wire format: `FafRequest` JSON `{relays: [{address, encrypted}], body: {key, message}}` (`FafRelay`, `FafBody`), `FAF_PATH`, `DEFAULT_RELAY_PORT`; re-exported at the `ttk_ra_client` root.
  - `src/seal.rs` — onion encryption: RFC 9180 HPKE (DHKEM(P-256), HKDF-SHA256, AES-256-GCM) to a node's RA-TLS cert key (`NodePublicKey` / `NodeSecretKey`); `seal_address`/`open_address`, `seal_body_with_key` (returns the `MessageKey`; the sealed plaintext is a 24-byte header (send time BE Unix secs ‖ 16-byte random message id) + message, AAD = `"ttk-faf/v2 message "` ‖ `body.key`; `seal_body_at`, `open_body_envelope` → `OpenedBody {key, message, message_id, sent_at}`, `unix_now`), `seal_response`/`open_response` (terminal reply under the message key); re-exported as `ttk_ra_client::seal`.
  - `src/egress.rs` — `classify_hop_address` / `HopAddressClass` (Public / Private / Forbidden): egress policy for peer-chosen destinations (relay next hops, `vsock-proxy` outbound); `is_permitted_hop_port` (443 or ≥ 1024); re-exported at the `ttk_ra_client` root. `is_instance_metadata_address` (`IMDS_V4`/`IMDS_V6`): the only Forbidden exception, opened solely by `vsock-proxy-tcp --allow-imds`.
  - `src/vsock.rs` (Linux) — quinn `AsyncUdpSocket`s over vsock, datagrams framed `[u16 BE len][payload]`: `VsockUdpSocket` (inbound) and `VsockOutboundSocket` (outbound via parent `3:5001`, `[4|6][ip][u16 port]` destination header); framing helpers reused by `vsock-proxy`. The enclave has no DNS: `resolve_via_parent` sends a resolve request on `5001` (`[0][u8 len][host][u16 port]`, `read_outbound_request` / `OutboundRequest`), the parent answers (`answer_resolve`, egress-filtered) `[u8 count]` + destination headers (≤ `MAX_RESOLVED_ADDRESSES`).
  - `src/replay.rs` — `ReplayGuard` (terminal `/faf` replay protection): accepts a body only if `sent_at` is within `FAF_FRESHNESS_WINDOW` (120 s) back / `FAF_MAX_CLOCK_SKEW` (30 s) ahead and its message id is new; ≤ `MAX_REMEMBERED_MESSAGES` ids (`ReplayError::{Stale, Replayed, Busy}`).
  - `src/vsock_proxy.rs` — `vsock-proxy` config: `RELAY_USAGE`, defaults, `RelayConfig`, `parse_relay_args`; inbound flow table `ClientTable` (`MAX_CLIENTS_PER_IP` 64; when full evicts the oldest client not yet confirmed by a QUIC 1-RTT packet from the enclave, `confirms_client`; `UNCONFIRMED_CLIENT_TIMEOUT` 30 s) (in the lib so `tests/` can reach it).
  - `src/vsock_proxy_tcp.rs` — `check_imds_request` (`--allow-imds` mode forwards only `PUT /latest/api/token` and body-less `GET …/iam/security-credentials[-extended]/[role]`, else closes); `vsock-proxy-tcp` config: `TCP_PROXY_USAGE`, `DEFAULT_TCP_VSOCK_PORT` (8001), `TcpProxyConfig`, `parse_tcp_proxy_args` (`TTK_ENCLAVE_CID`, `TTK_TCP_REMOTE`, `TTK_TCP_VSOCK_PORT`, `TTK_TCP_ALLOW_IMDS` / `--allow-imds`).
- `crates/ra-server/` — crate `ttk-ra-server` (lib `ttk_ra_server`), the attested server and the terminal node (`terminal`); no relay logic, no client. Does not depend on `ttk-ra-client`: `terminal` takes the `/faf` format and sealing from `ttk-core`.
  - `src/lib.rs` — declares `attestation`, `router`, `server`; re-exports `ttk_core::{egress, vsock}`; re-exports `cmw`, `Cmw`, `CmwRecord`, `CmwCollection`, `CmwType`, `AttestationParams`. Defines the `Evaluator` trait (decrypted `/faf` message → plaintext reply) and `EvalError` (`Send + Sync`); no implementations here (the terminal's is `ttk_storage::FileService`).
  - `src/attestation/` — providers (`nitro`, `sev_snp`, `tdx`, `mock`, `tsm`), `nitro_doc` (COSE parsing, mock docs, mock root key `mock_nitro_root_key.pk8`).
  - `src/server.rs` — attestation at startup, RA-TLS cert (`ATTESTATION_OID`, `create_cert_with_attestation`), QUIC/h3 accept loop; `Server::{bind, listen, serve, serve_with(Router), private_key_der, replace_certificate}`; `Listener::from_env()` (vsock `TTK_VSOCK_PORT` default `5000`, or `TTK_USE_UDP=1` UDP `TTK_LISTEN_ADDR` default `0.0.0.0:4433`); `PARENT_CID`, `MAX_REQUEST_BODY` (else 413), `REQUEST_BODY_TIMEOUT` (else 408), `MAX_IN_FLIGHT_BODY_BYTES` (1 GiB of bodies across all requests, a `BodyBudget`; else 503; sized for 4 GiB enclaves), `MAX_REQUEST_HEADERS`, `MAX_CONNECTIONS`, `MAX_CONNECTIONS_PER_SOURCE` (64 per IP, `SourceConnections`), `CERT_VALIDITY_DAYS` (30; warns `CERT_EXPIRY_WARNING` before, errors after; no renewal: restart + re-authorize), no TLS session resumption, no QUIC datagrams; `Server::listen` (bins) refuses the mock provider unless `TTK_ATTESTATION=mock`, `HANDSHAKE_TIMEOUT` (10 s), `CONNECTION_IDLE_TIMEOUT` (30 s with no request in progress, despite QUIC PINGs), `CONNECTION_MAX_AGE` (10 min, then GOAWAY + `CONNECTION_DRAIN_TIMEOUT`), `MAX_STREAMS_PER_CONNECTION`, `CONNECTION_RECEIVE_WINDOW`, `env_u32`.
  - `src/certificate.rs` — `CertificateStore` (rustls `ResolvesServerCert`): the presented RA-TLS chain, replaceable at runtime by a CA-issued cert for the same key + attestation extension that chains to the trusted roots (built-in `ttk_core::TTK_ROOT_CA_PEM` = `crates/core/src/certs/TTK_Root_CA.pem`, overridable by `Server::set_trusted_roots`; none = all refused) and names `CERT_DNS_NAME` (`enclave.internal`); `parse_chain` (PEM chain or one DER cert).
  - `tests/support/test_ca.rs` (tests only, no feature; not a test target) — trait `SignForTests` for `Server`: `sign_for_tests()` makes a throwaway CA the only trusted root, issues + installs a cert for the RA-TLS key via `Server::replace_certificate` (the `POST /certificate` path), unlocking the routes. Other crates' tests include it with `#[path = "../../ra-server/tests/support/test_ca.rs"] mod test_ca; use test_ca::SignForTests;` (dev-deps `rcgen`, `rustls`, `x509-parser`); node tests sign the `Server` before wrapping it (`Terminal::new` / `Relay::new` / `Root::new`; nodes have no `Server` accessor).
  - `src/terminal.rs` — `Terminal<E: Evaluator>` (wraps a `Server`, adds `POST /faf` last hop: non-empty `relays` = 400, must decrypt `body` or bare `400 invalid body`; stale/repeated body (`ReplayGuard`) = 409, guard full = 503; answers `Evaluator::eval(message)` (error = bare 500) sealed under the body's message key via `seal::seal_response`, which relays pass back unchanged), `Terminal::new(server, evaluator)`, `run(evaluator)`; no default evaluator.
  - `src/router.rs` — base routes only: `GET /`, `GET /evidence.cmw` (base64 CBOR CMW, generated at startup), `POST /evidence` (body = raw nonce, 1..=`MAX_NONCE_LEN` 512 bytes; base64 CBOR `FreshEvidence`: Evidence with the nonce in the Nitro doc and `user_data` = SHA-256 of the RA-TLS SPKI (like the startup Evidence); TDX/SEV-SNP report data = SPKI hash ‖ SHA-256(nonce) (`ttk_core::fresh_evidence::report_data`, checked by `verifier::verify_evidence_with_nonce`); plus the currently presented leaf cert; `MAX_CONCURRENT_ATTESTATIONS` else 503); `POST /certificate` (`CertificateStore::replace`: 204, or 400 malformed / 422 not the current cert / 403 untrusted / 503 no roots); `Evidence`; `CertificatePhase`. **Route gating** (in `build_router`, so it covers every route nodes add via `serve_with`): self-signed = only `POST /evidence` / `POST /certificate` served, everything else 404; after the (single) replacement (`CertificateStore::is_replaced`) those two are 404 and every other route is served, but only on connections that negotiated the CA-issued cert (`CertificatePhase` read before the handshake, attached per request by `server.rs`; none = locked). Locked routes answer 404 for every method (no 405).
- `crates/ra-client/` — crate `ttk-ra-client` (lib `ttk_ra_client`): everything client-side.
  - `src/client.rs` (re-exported at the crate root) — `TtkClient`, `ClientTransport` (UDP / vsock), `EnclaveCertVerifier` (accepts the self-signed or a CA-issued RA-TLS cert, CA signature unchecked; records it), `extract_attestation_doc`, `hex_encode`, `MAX_RESPONSE_BODY` / `MAX_RESPONSE_HEADERS`.
  - `src/verifier/` — evidence appraisal (`nitro`, `sev_snp`: VCEK via ASK or VLEK via ASVK (AWS signs with VLEKs); guest policy must not allow `MIGRATE_MA`, reserved bit 17 set, VMPL 0; `dcap`: PCK leaf must carry the Intel SGX extensions, TDX reports `tdattributes` and non-debug TDs need `SEPT_VE_DISABLE` (checked in `appraise`), `dcap`), `Policy`; `verify_evidence_with_nonce` for `POST /evidence` answers; `verify_evidence` takes `&dyn ImageTrustStore` and, for every non-debug TEE, checks `image_measurement` (Image: Nitro `pcr0`, SEV-SNP `measurement`, TDX SHA-384(`mrtd`‖`rtmr0..2`), SGX `mrenclave`; Signer: `pcr8`, `id_key_digest`, none for TDX, `mrsigner`) via `check_image_allowed`; the per-TEE verifiers (`nitro::verify`, `sev_snp::verify`, `dcap::verify`) do not check images; re-exports `TrustStore`, `ImageTrustStore`, `ImageMeasurement` (and `AmdRoots`/`AmdProduct` in `sev_snp`).
  - `src/trust/` — `TrustStore` (also at the crate root; vendor roots in `certs/`, mock root `ttk_core::MOCK_NITRO_ROOT_CERT`), `AmdRoots`/`AmdProduct`. Data only; verification lives in `verifier`.
  - `src/images.rs` — `RootImageTrustStore` (also at the crate root): `builtin()` blocks, fetching `GET /root-attestation` from `ROOT_SERVERS` (`a.root.ttk-servers.net:443`, `b.root.ttk-servers.net:443`, in order) with each root attested via `RootSignerTrustStore` (signer); fails closed (empty list). `fetch(roots, transport, verifier)` / `fetch_builtin(transport)` async; `set_root_transport` (relay sets vsock). `EnclaveCertVerifier` without `with_image_trust_store` uses a process-wide list fetched on a background thread (never under a lock): first needed by non-debug evidence or `prefetch_root_images()` (relay `run()` calls it), refreshed after `ROOT_IMAGES_REFRESH_INTERVAL` (10 min) while the old list stays in use, dropped after `ROOT_IMAGES_MAX_AGE` (1 h) without a successful refresh; only with no usable list does an appraisal wait (≤ `ROOT_FETCH_WAIT`); failures retried after `ROOT_FETCH_RETRY_INTERVAL`.
  - `src/lib.rs` — module wiring plus the `/faf` client side: re-exports `ttk_core::faf::{FafRequest, FafRelay, FafBody, FAF_PATH, DEFAULT_RELAY_PORT}` and `ttk_core::egress::{classify_hop_address, HopAddressClass}`; `parse_relay_address` (`"<server> <10-digit salt>"`), `parse_relay_server`, `connect_to_node`/`connect_to_node_filtered` (resolve via `resolve_node`: IP literals as is, system DNS over UDP, the parent's `vsock-proxy` over vsock). `ttk_ra_client::seal` = `ttk_core::seal`.
- `crates/relay/` — crate `ttk-relay` (lib `ttk_relay`): `Relay` (wraps a `ttk-ra-server` `Server`, adds `POST /faf` forwarding with a verified connection pool; empty `relays` = 400), `run()` (env config, `TTK_PARENT_CID`/`TTK_OUTBOUND_VSOCK_PORT`, `TTK_ALLOW_MOCK_ATTESTATION=1` for mock next hops, `TTK_ALLOW_PRIVATE_NEXT_HOPS=1` / `allow_private_next_hops()` for loopback/private next hops — needed locally and in relay tests). Egress policy via `ttk_core::egress::classify_hop_address` + `is_permitted_hop_port` (link-local/multicast/broadcast/unspecified always refused), next-hop addresses logged only at debug, bad relay entry = bare `400 invalid relay`, `MAX_RELAYS` (8), `MAX_CONCURRENT_FORWARDS` (256, else 503), pooled next-hop connections re-attested after `POOLED_CONNECTION_MAX_AGE` (10 min), every forwarding failure = uniform `502 relay failed`, answered ≥ `FAILURE_MIN_DELAY` (1 s) + jitter after the request.
- `crates/root/` — crate `ttk-root` (lib `ttk_root`): `Root` (wraps a `ttk-ra-server` `Server`, adds `GET /root-attestation`: JSON `RootAttestation` `{measurements: [hex…]}`, the accepted enclave image measurements from `FileImageTrustStore` (`src/image_allowlist.txt`); `with_image_trust_store` overrides), `run()`. Depends on `ttk-core`, `ttk-ra-server` and (for `auth`) `ttk-ra-client`; `ttk-ra-client` dev-depends on it (`tests/images_tests.rs`); `tests/root_tests.rs` has its own minimal h3 client (no RA-TLS verification).
  - `src/auth.rs` (always built: pulls in `ttk-ra-client`, `rcgen`) — test CA: `CertificateAuthority` (`from_pem` (any CA; subject rebuilt for rcgen; no CA generation), `issue`: leaf for the node's RA-TLS SPKI with the same attestation extension, `CERT_DNS_NAME`, subject CN = the given common name (`authorize` passes its server name), valid from now for `ISSUED_CERT_VALIDITY_DAYS` (365), chain incl. the CA unless it is a root), `authorize`: RA-TLS connect, `POST /evidence` with a random nonce (`verify_fresh_evidence`: response cert = TLS handshake cert byte for byte, Evidence bound to its key via `verify_evidence`, Nitro nonce, same measurements as the cert's Evidence), then `POST /certificate` (expects 204). Images default to `FileImageTrustStore::builtin()`. Tests in `tests/auth_tests.rs`.
- `crates/storage/` — crate `ttk-storage` (lib `ttk_storage`): what the terminal (`ttk_ra_server::terminal::Terminal`) stores: the file service evaluator and the blob stores. Re-exports only `ttk_ra_server::EvalError` (in `BlobStore`'s signatures); public API is just what the bins need (`FileService::new`, `BlobStore`, `MemoryStore::new`, `S3Store::from_env`), the rest is private and tested through `Evaluator::eval` / `from_env`.
  - `src/lib.rs` — `FileService<S: BlobStore>` evaluator (wire types from `ttk_core::file_message`), CBOR with byte strings (no base64): `{"type": "upload", "body": h'<file>'}` → `{"response": h'<32-byte sha256>'}`, `{"type": "download", "body": h'<sha256>'}` → `{"response": h'<file>'}` or, if missing, `{"error": "not_found"}` (`FileResponse::Error(FileError::NotFound)`, sealed like any reply; `BlobStore::get` returns `Option`, S3 `NoSuchKey` = `None`); `FileRequest`/`FileResponse` `to_cbor`/`from_cbor`; content-addressed (blob name = hex sha256, `blob_name`). Evaluator/store errors are `EvalError` (`Send + Sync`, unlike `BoxError`).
  - `src/adaptors/` — `BlobStore` trait, `local_memory::MemoryStore` (tests, `local-mem-server`; at `adaptors::local_memory::MemoryStore`), `s3::S3Store` (feature `s3`, non-default: `TTK_S3_BUCKET`, optional `TTK_S3_ENDPOINT`, AWS env credential chain, rustls/`ring`; `TTK_S3_VSOCK_PORT` (Linux) = S3 over vsock: `LoopbackResolver` sends every host to `127.0.0.1:443`, forwarded to the parent's `vsock-proxy-tcp`; `TTK_IMDS_VSOCK_PORT` (Linux, empty = unset) = credentials from the parent's instance role: `ImdsCredentialsProvider` at `http://127.0.0.1:80`, forwarded to the parent's `vsock-proxy-imds`).
- `crates/executables/` — crate `ttk-executables`: **every binary** lives here (`src/bin/<name>.rs`); the other crates are libraries only. Its own small lib (`ttk_executables`) holds only what several bins share. Features `nitro`/`mock`/`sev-snp`/`tdx` forwarded to the node crates, `s3` (→ `ttk-storage/s3`).
  - `src/lib.rs` — declares `faf_client` only.
  - `src/faf_client.rs` — shared core of the `/faf` client bins (`client`, `client-m`): `DEFAULT_SERVER_ADDR` (`127.0.0.1:4433`), `DEFAULT_SERVER_NAME` (`localhost`), `DEFAULT_RELAY_SERVER` (`127.0.0.1:4434`), `DEFAULT_TERMINAL_SERVER` (`127.0.0.1:4444`); `Route` / `RouteArgs` (`new(TTK_SERVER_ADDR, TTK_SERVER_NAME)`, `parse_arg` for `--server-name`/`--addr`/`--relay`/`--terminal`/positional URL, `build`); `parse_process_args(parse, usage)` (help = usage + exit 0, invalid = exit 2); `send(route, message)`: connects to the entry relay, attests the second relay and the terminal, seals each hop address to the relay reading it and the body to the terminal, `POST /faf`, logs the response, returns the decrypted reply (`None` if not 200; errors fatal); `attest_node`; `ClientError` (`Send + Sync`).
  - `relay.rs`, `root.rs` — enclave nodes: `env_logger` + `ttk_<node>::run()`.
  - `s3-server.rs` — bin `s3-server` (`required-features = ["s3"]`): the file service terminal node, `Terminal::new(Server::listen(Listener::from_env()?)?, FileService<S3Store>)` (its own `run`).
  - `local-mem-server.rs` — bin `local-mem-server`: like `s3-server` but with an in-memory `MemoryStore` (no S3, nothing persisted).
  - `echo.rs` — bin `echo`: a terminal node whose evaluator (`Echo`, defined in the bin) replies with the decrypted message unchanged; everything is in that file.
  - `vsock-proxy.rs` — bin `vsock-proxy` (Linux, parent instance: public UDP `:443` to enclave vsock `5000`, and outbound vsock `5001` to UDP, egress policy via `egress`, `--allow-private`; also answers the enclave's DNS resolve requests on `5001`).
  - `vsock-proxy-tcp.rs` — bin `vsock-proxy-tcp` (Linux, parent instance): vsock `8001` (enclave CID only) to one **fixed** TCP remote (`--remote host:port`, e.g. the S3 endpoint), resolved on the parent, egress policy via `egress`; opaque bytes (TLS ends in the enclave).   - `client-m.rs` — **test-only** bin `client-m`, over `faf_client`: `--message <TEXT>` (required) sent as raw UTF-8, the decrypted reply logged as text (`<-- Reply: …`). ## Features (`ttk-ra-server`; `ttk-relay` / `ttk-storage` / `ttk-root` / `ttk-executables` forward them)
- `nitro` and `mock` are default; `sev-snp`, `tdx` optional; all additive. `mock` is the fallback when no TEE hardware is detected (node binaries need `TTK_ATTESTATION=mock` to accept it; `Server::bind` in tests doesn't); mock document creation (`nitro_doc::create_mock_attestation_document`, the mock root key) is compiled only with `mock`.
- `ttk-ra-client` depends on `ttk-core`, not `ttk-ra-server` (only its tests do, dev-dependency with `mock`, `sev-snp`, `tdx`). `ttk-core` has no features.
- `tokio-vsock` is only pulled in on Linux.
- `ttk-ra-client` dev-depends on `ttk-ra-server`/`ttk-relay`/`ttk-storage`, which depend on it (a dev-dependency cycle): in client tests, don't pass `ttk_ra_client` types into relay/terminal APIs (use `Relay::allow_mock()`).

## Commands
```bash
cargo build --workspace
cargo test --workspace                        # nitro tests fall back to mock docs off-enclave
cargo test --workspace --all-features
# Nodes serve nothing but POST /evidence + /certificate until authorized (certify-server below, with the TTK root CA's cert + key)
TTK_ATTESTATION=mock TTK_USE_UDP=1 cargo run --bin relay           # relay node on UDP :4433 (TTK_LISTEN_ADDR overrides; RUST_LOG=info for logs)
TTK_S3_BUCKET=<bucket> AWS_REGION=<region> TTK_USE_UDP=1 cargo run --bin s3-server --features s3
TTK_ATTESTATION=mock TTK_USE_UDP=1 TTK_LISTEN_ADDR=127.0.0.1:4455 cargo run --bin root   # GET /root-attestation
TTK_ATTESTATION=mock TTK_USE_UDP=1 TTK_LISTEN_ADDR=127.0.0.1:4444 cargo run --bin echo   # terminal echoing each /faf message
TTK_ATTESTATION=mock TTK_USE_UDP=1 TTK_LISTEN_ADDR=127.0.0.1:4444 cargo run --bin local-mem-server   # file service terminal, in-memory store
cargo run --bin client -- <args>              # see parse_client_args() in crates/executables/src/bin/client.rs
cargo run --bin client-m -- --message "hello" # text message (e.g. to echo); TTK_ALLOW_MOCK_ATTESTATION=1 for mock nodes

## Conventions
- Tests live in each crate's `tests/` (no inline `#[cfg(test)]` modules); items they need must be `pub`.
- Rust 2021; run `cargo fmt` and clippy before finishing. Keep `//!`/`///` doc comments on public items, in the existing RATS/RFC-referencing style.
- Logging via `log` + `env_logger` in code; do not use `eprintln!` , `println!` or `dbg!`.
- Crypto: rustls 0.23 with the `ring` provider (installed explicitly when attesting / connecting); quinn 0.11 + h3 0.0.7 / h3-quinn 0.0.9 — versions are tightly coupled, upgrade together.
- Releases use conventional commits (`feat:`, `fix:`, `chore(release):`) and version bumps of `[workspace.package]` in the root `Cargo.toml`.
- **Branches:** `develop` is the integration branch; all PRs target `develop` (`gh pr create --base develop`), never `main`. Branch names MUST start with `bugfix/`, `feature/` or `docs/`. `main` is the release branch: it only receives merges from `develop`, and every push to it runs CD (`main.yml`: version bump + tag). CI (`CI.yml`) runs on every PR.
- **STRICT commit message rule:** every commit message MUST start with one of these prefixes, no exceptions:
  - `fix:` — bug fixes
  - `feat:` — new features (minor version bump)
  - `major:` — breaking changes (major version bump)(In case of `major:` ask me first)

  Never write an unprefixed commit message. (`chore(release):` is reserved for the automated release bump.)

## Gotchas
- `EnclaveCertVerifier` intentionally skips CA validation (a CA-issued cert from `POST /certificate` is accepted without checking its issuer); trust comes from checking the attestation doc and that its `user_data` matches the cert/key hash. Don't reuse it outside RA-TLS flows.
- The CMW wrapper is unsigned: trust comes only from the wrapped TEE evidence. The verifier dispatches on the CMW type (`TeeKind::from_cmw`), never on anything else in the wrapper.
- Routes are locked until a CA-issued cert is installed (see router.rs above): tests that start a node and call anything but `POST /evidence`/`/certificate` must call `sign_for_tests()` first; tests of the bootstrap routes must not.
- The RA-TLS cert and `/evidence.cmw` carry evidence generated once at startup (no nonce); freshness only via `POST /evidence`.
- The terminal evaluates each sealed `/faf` body once: tests that resend a request must seal a fresh body (`seal_body_with_key`) each time, or expect 409 (502 through a relay).
